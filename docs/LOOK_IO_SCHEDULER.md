# 防饥饿 LOOK I/O 调度器

## 1. 目标与边界

`look` 是面向 Linux 3.0 elevator 接口新增的独立 I/O 调度器。它以传统
LOOK 磁盘调度为主策略，并增加 FIFO 超时抢占，目标是在旋转磁盘上减少
无意义的磁头往返，同时避免持续单向请求让另一方向的请求无限等待。

本实现不改变系统调用、块层用户态 ABI 或现有调度器。CFQ 仍是默认调度器，
`look` 需要通过 Kconfig 启用，并由启动参数或 sysfs 选择。本仓库不是完整
Linux 3.0 源码树；CI 会把相关文件覆盖到官方 Linux 3.0 源码后完成构建。

## 2. 数据结构

- `sort_list`：以请求起始扇区为键的红黑树，用于在 `O(log n)` 时间内插入、
  删除并寻找当前磁头两侧最近的候选请求。
- `fifo_list`：按到达顺序保存同一批请求，用于 `O(1)` 找到等待最久的请求。
- `head_sector`：最近一次已派发请求的结束扇区，初始值为 0。
- `direction`：当前扫描方向，初始为向高扇区方向。

每个尚未派发的请求必须同时位于红黑树和 FIFO 中。派发、合并和退出路径都
检查或维护这一不变量。

## 3. 调度规则

每次派发按以下顺序选择一个请求：

1. 如果 FIFO 头部请求已经超过等待期限，立即选择它，并将扫描方向调整为
   从当前磁头位置指向该请求的方向。
2. 否则，在当前扫描方向选择距离磁头最近的请求。
3. 如果当前方向已经没有请求，则反转方向并选择另一侧最近的请求。
4. 从红黑树和 FIFO 同时删除请求，把 `head_sector` 更新为该请求的结束扇区，
   再交给块层派发队列。

这是一项“软”等待上限：它保证超时请求优先进入块层派发队列，但设备固件、
驱动队列和已经派发的请求仍可能影响实际完成时间。

## 4. 合并处理

- 保留块层原有的后向合并机制。
- `front_merges=1` 时，通过红黑树精确查找前向合并候选。
- 前向合并改变请求起始扇区后，会先从红黑树删除再重新插入。
- 两个请求合并时保留更早的 FIFO 到期时间，并完整移除被合并请求。
- 相同起始扇区无法同时作为红黑树键存在时，先派发已经排队的请求，再插入
  新请求，与 Linux 3.0 deadline 调度器处理重复键的方式一致。

## 5. 配置与使用

Kconfig 选项：

```text
CONFIG_IOSCHED_LOOK=y       # 内建
CONFIG_IOSCHED_LOOK=m       # 模块
CONFIG_DEFAULT_LOOK=y       # 可选：设为默认调度器
```

本项目保留 `CONFIG_DEFAULT_CFQ=y`。启用或加载 `look` 后，可按设备切换：

```sh
cat /sys/block/sda/queue/scheduler
echo look > /sys/block/sda/queue/scheduler
```

调度器参数位于 `/sys/block/sda/queue/iosched/`：

- `max_wait_ms`：FIFO 等待阈值，默认 1000 毫秒。设为 0 后，每次都由 FIFO
  头部请求抢占，调度行为等价于按到达顺序派发。修改只影响随后入队请求已经
  计算的到期时间。
- `front_merges`：是否主动查找前向合并，只接受 0 或 1，默认 1。

## 6. 验证范围

- 共享策略单元测试覆盖空队列、两个方向、边界反转、超时抢占和方向更新。
- 源码契约检查调度器注册、回调、Kconfig、Makefile、合并路径及 CI 覆盖。
- 使用 GCC 4.8.5 在官方 Linux 3.0 源码中编译调度器对象和块层聚合对象，
  并完成 `vmlinux` 链接。

本轮不包含 QEMU 启动、真实磁盘压力测试或性能基准，因此不据此声称运行态
吞吐量或延迟优于 CFQ、deadline 或 noop。
